What's new

Release notes for each protocol version. Upgrade the server and all clients together.

Cipher

  • AES-256-GCM when both ends have hardware AES, signed so it can't be downgraded
  • ChaCha20-Poly1305 in assembly with the XChaCha subkey cached per session

Data path

  • TCP receive coalescing on Linux TUN writes
  • Constant-time replay window, checked once in arrival order
  • Cached keys, shared clock, batched TUN writes, large socket buffers

Network

  • IPv6 inside the tunnel with NAT66, and IPv6 endpoints
  • WireGuard-style cookie flood protection

Stealth

  • Ghost relays a real site's handshake byte for byte
  • Phantom server flights shaped like real QUIC, with continuing connection IDs
  • Per-client stealth keys, cover rotation, mask servers by host name
  • TLS-over-TCP fallback with a cover web backend

Handshake

  • Plain handshakes in 2–6 ms, Phantom in about 20 ms

Security

  • Noise IK: the client proves its static key in the first message
  • Authenticated timestamps; identical retransmits get the cached reply
  • Per-client inner source checks and identity-bound addresses
  • Validated ML-KEM keys, hedged ML-DSA signing with a context string

Reliability

  • Pending keys promoted on first use, so a lost reply can't stall the tunnel
  • Reconnect on a fresh socket, one state machine checked every second
  • Clean shutdown restores routes, DNS and IPv6 settings

Performance

  • Per-flow dispatch keeps each TCP flow in order
  • Capped UDP GSO runs and the real tunnel MTU

Stealth

  • Handshakes wrapped in QUIC short headers with header protection
  • Single-use Initial connection IDs; probes are relayed to the cover site

Highlights

  • First hybrid X25519 + ML-KEM handshake with ML-DSA server signatures
  • Direct-IO workers for the data plane
  • Ghost mode prototype with timing smoothing
